# Android 滚动卡顿真机诊断与回归

日期：2026-10-17。设备为无线 ADB 连接的 23127PN0CC（houji），Android 16、1200 × 2670、120Hz。原安装为 `com.lonzzi.nekofin` / 0.1.0 (174)。对照与最终验证使用同一真机、同一服务器上的独立 `com.lonzzi.nekofin.dev` **Release** 包，保留原安装和数据。

> 后续更新：本报告所称“最终包”为滚动修复阶段产物。后续已核对上游并改用 Reanimated 4.5.5，删除清理器本地 patch；路由遮罩修复见 [后续诊断](./android-route-jank-2026-10-17.md)。原始对照数据仍保留。

## 故障链

1. Reanimated 4.5.1 的 `PropsRegistryGarbageCollector.registerView` 对共用 native tag 的嵌套 AnimatedComponent 去重。
2. `unregisterView` 原实现对重复或未登记的 tag 仍减少 `viewsCount`。例如 GestureDetector 与 Animated.View 共用一个原生 View，重复卸载可提前清除 500ms 的属性回收定时器，使计数与存活 View 集合不一致。
3. 回收停止后，已结束动画的属性无法按时同步回 React 并从原生属性登记表清除。
4. Android 惯性滚动在绘制中触发滚动回调。Reanimated 的 `performNonLayoutOperations → getPendingUpdates` 会复制并重放整个属性登记表，积压越多，主线程同步属性赋值越重。

初始原进程中，已确认的 FX 详情页惯性阶段 traversal 平均 19.015ms，App Deadline Missed 为 240/248（96.77%）；拖动阶段为 5/438（1.14%）。重启原安装进程后减速恢复，说明需要检查进程内状态，不能把重新构建或重启本身当作修复。

## 受控故障对照

关闭头图遮罩、背景图或底部实时模糊，未明显降低滚动回调耗时。关闭视差同步则降低拖动回调开销。进一步加入临时调用标记和登记表负载，验证属性清理失效与惯性阶段同步重放的关系。

对照负载：共享详情组件额外挂载不可见的已结束动画属性，重复执行共用 tag 的注册/卸载序列。保留原来的 Reanimated 头图视差，排除换动画驱动对这组结果的影响。每组 6 次相同上下滑动，Perfetto 记录 14 秒，未同时录屏。三份关键 trace 均无 buffer overwrite / data loss。

| 场景                             | JS 计数 / 实际登记 View | 清理定时器 | 绘制中重放属性数 | 减速 traversal 平均 | 减速应用帧超时  |
| -------------------------------- | ----------------------- | ---------- | ---------------- | ------------------- | --------------- |
| 原实现，重复卸载后               | 0 / 2015                | 停止       | 2001             | 26.196ms            | 173/175，98.86% |

## 最终修改

- Bun patch 修复 Reanimated 属性回收器：只处理实际存在的 tag，以 `viewsMap.size` 维护计数。源码及包的编译 JS 入口一并修复。
- Android 头图视差使用 React Native Animated 的 `useNativeDriver: true`，保留原来的位移/缩放曲线、头图遮罩及背景效果，降低拖动时的同步处理开销；其他平台继续使用原来的 Reanimated 视差。
- 原生 Tab 模糊源改为胶囊附近的 RenderNode 快照，沿用 BlurView 的半径、缩放、噪声和系统绘制路径。采样范围留出三倍有效模糊半径及拖动余量，避免边缘截断；不重复绘制整棵 View。Android 12 以下沿用原来的实色背景。
- Tab 点击、拖动、弹簧选中效果、胶囊轮廓及路由过渡代码保持不变，已与修改前源文件逐字比较。
- BlurView 的包内桥接 Java 源文件通过 Gradle Copy 任务加入生成源目录，避免 Bun 在嵌套目录新增补丁文件时的安装错误。
- 临时 receiver、模式开关、压力节点、属性计数标记和 profileable 配置均不保留在最终代码中。

## 回归

- 原依赖的生命周期回归：4 项中 3 项失败；补丁后 4 项通过，覆盖重复清理仍有其他存活 View、重复卸载后新 View、重复注册和未知 tag 清理。
- 完整单测：75 个文件 / 473 项通过。
- TypeScript、相关 ESLint、Prettier、冻结 lockfile 安装通过。
- Android ARM64 Release 构建通过：`./gradlew :app:assembleRelease --offline -PreactNativeArchitectures=arm64-v8a`。
- 最终 APK 未发现实验 receiver、压力组件、计数标记或绕过绘制保护的开关；Reanimated 与原始 npm 包对比，仅两个属性回收器 JS/TS 文件不同。
- 真机原生 tab 验证：从“搜索”拖动到“首页”，再拖动到“设置”，点击回“搜索”，逐次检查原生 selected 状态，并确认原来的 FX 详情路由保留。
